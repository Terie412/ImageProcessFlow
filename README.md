# ImageProcessFlow

纯本地的**可视化图像处理流水线编辑器**。在画布上摆节点、连线，把若干处理步骤编排成一条流水线，手动逐步执行。

当前版本只有一个处理节点：**Qwen 生图 / 编辑**（阿里云百炼 DashScope）。改分辨率、裁剪等脚本按同样的方式随时可以加进来。

---

## 快速开始

```bat
start.bat                          :: 不带参数启动，界面里再选工作目录
start.bat -w D:\workspace\myproj   :: 直接指定工作目录
```

然后浏览器打开 **http://127.0.0.1:8770**

首次使用需要设置环境变量 `DASHSCOPE_API_KEY`（在系统环境变量里配好，或者启动前 `set`）。

### 基本操作

1. **指定工作目录** —— 顶栏「工作目录」。所有图片和画布都放在里面，工具**不会碰目录以外的任何文件**。
2. **加数据节点** —— 把图片直接拖进画布，或用「＋ 导入图片」。图片会被**复制**一份进工作目录。
3. **加处理节点** —— 在画布**空白处点右键**，从菜单里选要创建的节点（菜单里也能导入图片）。
4. **连线** —— 从图片节点右侧的圆点拖到处理节点左侧的输入口。
5. **填提示词** —— 节点左边那栏就是输入口，**从上到下数第几行**，提示词里就写 `参考图N`，例如 `抠图：只保留参考图1中的人物`。提示词**原样发给模型**，不做任何改写。写不好可以点输入框右侧的 **「润色」**，让它帮你重写一版（见下方「提示词润色」）。
6. **点「▶ 执行」** —— 底部弹出日志，跑完会在右侧长出输出图片节点，节点右下角会显示这次执行的耗时。

### 几个操作习惯

- **看大图：双击任意图片节点** —— 全屏查看器里默认「适应窗口」，点「实际大小」可以按 1:1 看（超出就滚动），**双击图片**也能在两种模式间切换。透明区域下面是**棋盘格**，抠图结果哪里透明一眼可见。`Esc` 或点暗处关闭
- **编辑裁剪区域：双击裁剪节点上的区域预览图**（或点「编辑」）—— 拖空处新建、拖框内移动、拖四角改大小、选中后 `Delete` 删除；**点「保存」才写回**
- **删除节点：选中后按 `Delete` 或 `Backspace`** —— 这是唯一的删除入口，节点上没有删除按钮。**弹层开着时这个键不会生效**（免得误删画布上的节点）
- **只有删数据节点才可能弹确认框**（它对应磁盘上的图片文件，会永久删除）；删处理节点和连线是静默的。嫌烦的话，**顶栏右侧的齿轮 ⚙ → 取消勾选「删除数据节点前弹出确认」**，之后删除立即生效
- **增减输入口**：每个输入口行右边的 `−` 删掉**这一个**，输入口栏最下方的 `＋` 在末尾加一个。删掉中间的之后，后面的会自动前移（`参考图3` → `参考图2`），挂在它上面的连线跟着走 —— **提示词里写的序号不会自动改，需要你自己同步**
- **输入口栏只显示序号**（`1`、`2`…），省地方；**鼠标悬停**能看到完整名字（`参考图1`）以及它当前连的是哪张图。连上的口，左边的圆点和数字会变亮
- 拖动节点要按在**空白处**；按在输入框、下拉框、按钮上是操作控件，不会挪动节点
- **节点摆乱了**（比如输出的图片叠在一起）：在**画布空白处点右键 →「画布 → 重排输出节点」**，会把所有输出节点重新摆到各自处理节点的右侧、按顺序纵向排开
- **改节点大小**：拖节点**右下角的小方块**。改完会记住（刷新不丢）。处理节点默认是横向的 600×340，方便容纳长提示词
- **每种处理节点类型的最小尺寸可以分别调**：**齿轮 ⚙ → 节点最小尺寸**，里面按**具体的节点类型**列出（数据节点、以及每个已注册的处理节点各一行，如「Qwen 生图 / 编辑」），允许 80~4000，改完节点立刻按新下限重排
- **选中一个节点**，画布左上角会显示它的**宽 × 高**；拖右下角改大小时这个数字实时跟着变
- 节点的**分辨率、格式、耗时**都显示在标题栏右侧，不占节点主体
- 处理节点下方的配置（模型 / 尺寸 / 张数 / 三个开关）**最多占两排**：宽度够就挤成一排，不够才折行；把节点拖宽能挤得更紧

## 从零开始（克隆后首次运行）

克隆下来的仓库**只有源码** —— 依赖、构建产物、工作目录数据都被 `.gitignore` 排除了，所以第一次跑之前要先搭环境。三步：

```bat
:: 1) 后端依赖。venv 必须建在 runtime\venv（start.bat 写死了这个路径）
python -m venv runtime\venv
runtime\venv\Scripts\python.exe -m pip install -r requirements.txt

:: 2) 前端构建。产物输出到 server\static —— 不构建的话界面打不开
cd web && npm install && npm run build && cd ..

:: 3) 起服务
start.bat
```

然后浏览器打开 **http://127.0.0.1:8770**。

### 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | **3.10+**（实测 3.14.4） | 只跑后端。上面命令里的 `python` 换成你自己的解释器路径 |
| Node.js | **18+**（实测 22.x） | **只在构建前端时需要**，跑起来之后用不到 |
| `DASHSCOPE_API_KEY` | 环境变量 | 阿里云百炼的 key。不配则**生图节点执行失败**，其他功能不受影响 |
| `DEEPSEEK_API_KEY` | 环境变量（可选） | 只有用「提示词润色 / 裁剪自动识别」才需要 |

> 国内装依赖慢的话：pip 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`（`web/.npmrc` 里已经配好了 npmmirror）。
> 不想让 pip 缓存落到 C 盘就再加 `--cache-dir runtime\pip-cache`。

### ⚠️ 三个最容易卡住的地方

1. **venv 路径不能改。** `start.bat` 里写死了 `runtime\venv\Scripts\python.exe`。想用别的解释器就别走 bat，直接跑
   `python server\main.py -w <工作目录>`。
2. **必须先 `npm run build`。** `server/static` 是 vite 的构建产物、不在仓库里。没有它服务照样起得来，但打开 8770 是 **404** —— 后端只在 `server/static` 存在时才挂载静态目录（`server/main.py` 里那句 `if STATIC_DIR.is_dir()`）。做前端开发时改用 `npm run dev`（见下方「开发」）。
3. **`npm install` 可能漏装 optional 依赖。** 某些沙箱环境会往 Node 进程注入 `NODE_OPTIONS` 垫片，导致 `@rollup/rollup-win32-x64-msvc` / `@esbuild/win32-x64` 漏装，`vite build` 报 `Cannot find module @rollup/...`。补装命令见「开发」一节。

> 首次启动**不会有 `settings.json`**，这是正常的 —— 程序会用默认值生成，它是本地偏好、已被 gitignore。

## 提示词润色

提示词框**右侧**（贴着这一行的底部）有个 **「润色」** 按钮。点它会把 **当前提示词 + 这个节点连着的所有参考图 + 该生图模型的使用特点** 一起发给一个文本模型（DeepSeek），拿回改写后的提示词，**直接替换**框里的内容；替换后按钮上方会出现 **「撤销」**，点一下还原。润色后内容通常会长不少，可以用鼠标滚轮在框里翻。

**它解决什么问题**：生图模型对「背景」「UI」这类抽象说法完全没法定位，会把画面内容整个删掉（返回一张全透明的图）。润色就是把这些话**展开成具体的视觉描述** —— 例如把「去掉上层的所有 UI」展开成「删除顶部的状态栏、顶部的四个文字标签、中间的提示卡片和按钮、底部的五个图标」。

**用之前先配一次密钥**：顶栏 `⚙` → 「提示词润色（DeepSeek）」里填**环境变量的名字**（默认 `DEEPSEEK_API_KEY`），程序运行时去读这个环境变量拿真正的 key —— key 本身**不会**存进配置文件，也不会显示在界面上。没配或环境变量不存在时，按钮会报错并说明原因。

**模型特点文件**：`MODEL_NOTES.md` 记录各个生图模型的脾气（提示词该怎么写、什么任务做不好、踩过哪些坑）。润色时只把**当前节点所选模型**那一节喂给文本模型。以后加了新的生图模型，在文件里追加一节 `## <模型 id>`（id 要和 manifest 里 `model` 的取值一致）就行。

> ⚠️ 润色只是"把话说明白"，**不会**让生图模型变得更能干。如果问题出在模型能力本身（比如它根本删不掉界面元素），润色帮不上忙 —— 得换思路或换模型。

## 裁剪节点

把一张图**按区域裁成多张**。节点上只有一个输入口（没名字，接上待裁剪的图就行）、一块**区域预览缩略图**，和三个按钮：

| 按钮 | 作用 |
| --- | --- |
| **自动识别** | 让模型看一眼这张图，挑出最合适的切分参数，再由一个**纯几何算法**（`scripts/_shared/extract_elements.py`）把区域算出来，直接覆盖当前区域数组。点错了可以**撤销** |
| **编辑** | 打开区域编辑器（**双击缩略图**也是同一个入口） |

**自动识别是怎么工作的**：模型**只挑参数、不给坐标** —— 边界由算法算，因为模型对像素级边界没概念，而切图差几个像素就切到内容上了。它拿到的是「这张图 + 一份参数卡（脚本说明 + 每个参数的范围和含义）」，返回 `{"args": {...}, "reason": "…"}`；服务端校验后跑脚本、读回区域坐标。整个过程**不产生任何图片费用**，只有一次很便宜的文本模型调用。

**区域编辑器**：在图上**拖空处新建框**、**拖框内移动**、**拖四角改大小**、选中后按 `Delete` 删除；右侧一列可以直接改 `X / Y / W / H`（**原图像素**）或单条删除。**点「保存」才写回节点**，取消不动。

**执行**：按区域逐条裁剪，每个区域一张图，挂在节点右侧（和生图节点的多输出一样）。**区域为空时会报错并且不动旧输出**；某个区域完全落在图像外也会报错（多半是上游换了图，重新识别一下）。

> 这个节点**没有提示词**：它是纯几何切分，不区分"按钮"和"图标"，也不需要区分。想只要其中几个元素，就用编辑器手动删掉不要的框。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| **数据节点** | 一张图片。分「输入型」（你拖进来的）和「输出型」（节点产出的） |
| **处理节点** | 执行一个脚本。有输入口、输出口、参数控件 |
| **图片名** | 每张图有全局唯一的短名 `A`、`B`、`C`…，文件名主干就是它。**只用来标识文件和节点**（缩略图徽标、删除时点名），不参与提示词。节点的标题栏右侧还会显示该图的**分辨率与格式**（如 `941×1672 · PNG`） |
| **引用输入图** | 在提示词里写 `参考图N`（N = 输入口栏里从上往下数的序号）。引擎**原样透传**，不做替换 |
| **输出槽位** | 处理节点的第 N 个输出。它是「投影」—— 重执行时按序号原位置刷新；**新建的槽位**摆在处理节点右侧一列，纵向按序号排开（间距按节点实际大小算，不会叠在一起） |
| **裁剪区域** | 裁剪节点上的一组矩形 `{x,y,w,h}`，坐标是**原图像素**、原点左上。它是个**参数**（不是端口），可以在节点上双击预览图编辑 |

### 执行语义（要点）

- **改参数不触发任何重算**，必须手动点执行
- 执行一个节点**只跑它自己**，不会级联下游
- 执行后，**直接下游处理节点被标脏**（紫色圆点），提示你它需要重跑
- 重执行后按**输出序号**重新绑定：序号还在 → 连线保留、图原地刷新；序号没了 → 连线断开、**文件永久删除**
- 执行**失败**时旧输出原封不动（脚本先写临时目录，成功了才搬运）

完整规则见 [`DESIGN.md`](DESIGN.md) §2.2。

### 工作目录长什么样

```
<工作目录>/
├─ graph.json       画布结构（节点 / 连线 / 参数）—— 打开它所在的目录就是打开项目
├─ images/          所有图片，文件名主干 = 图片名

│  └─ B.png
├─ .tmp/            执行中的临时输出，成功后搬运进 images/
```

## 新增一个处理节点

1. 在 `scripts/` 下建一个目录，放一个 `manifest.json` 和一个 `.py`
2. 顶栏点「重新加载脚本」，新节点立刻出现在画布右键菜单里

**manifest 能声明什么**

```jsonc
{
  "id": "my_script",
  "name": "显示在节点上的名字",
  "entry": "my_script.py",

  // 输入口。dynamic: true → 节点上出现 −/＋ 可增减数量，展开成 image1 / image2 / …
  "inputs": [
    { "key": "image", "type": "image", "dynamic": true, "label": "参考图",
      "count": 1, "min": 0, "max": 10 }
  ],

  // 参数。primary: true 的那个占据节点主体，其余紧凑排在下方。
  // type 可选：text / number / enum / bool / regions（区域数组，见下）
  "params": [
    { "key": "prompt", "type": "text",   "label": "提示词", "primary": true, "default": "" },
    { "key": "model",  "type": "enum",   "label": "模型", "width": "grow",
      "options": [{ "value": "a", "label": "模型 A" }] },
    { "key": "n",      "type": "number", "label": "张数", "width": "narrow", "default": 1 },
    { "key": "flag",   "type": "bool",   "label": "开关", "default": false }
  ],

  "outputs": [{ "key": "image", "type": "image", "multi": true }]
}
```

> `width` 可选 `grow`（吃掉整排剩余宽度）/ `narrow`（定宽小格）/ `full`（独占一排），不写就是普通宽度。
> `options` 既可写成字符串数组，也可写成 `{value, label}` 对象。
> **不要写 `hint`** —— 低频说明不占 UI 空间，统一放文档里。

**`regions` 类型**（裁剪节点用的那种区域数组）：参数值就是
`[{"x":0,"y":0,"w":100,"h":50}, …]`（**原图像素**、原点左上）。节点上渲染成「区域预览缩略图 + 撤销 / 自动识别 / 编辑」，双击缩略图打开编辑器。取哪张图做预览，默认用**第一个输入口**，也可以显式写 `"source": "image"`。

**`detect` 段**（可选）：声明这个节点支持「自动识别」，以及**模型可以调哪些脚本参数**。写法见 `scripts/crop/manifest.json`，机制见 DESIGN.md §3.8。

**脚本契约**（详见 DESIGN.md §2.5）：

```
stdin  ← 一行 JSON: {"params": {...}, "inputs": {"image1": 路径或 null}, "output_dir": 目录}
stdout → 日志，原样显示在节点面板上
产出   → 把图片写进 output_dir，命名 0.png、1.png…（序号即输出槽位顺序）
成败   → 退出码 0 = 成功；非 0 = 失败，错误写 stderr
```

没有结果 JSON、没有回调、没有进度协议 —— 引擎只关心「退出码 + 目录里有什么文件」。

### ⚠️ 重装前端依赖时的坑

WorkBuddy 会往所有 Node 进程注入 `NODE_OPTIONS=--require=...node-language-shim.cjs`，这个垫片会让 **npm 漏装 optional 依赖**（`@rollup/rollup-win32-x64-msvc`、`@esbuild/win32-x64`），表现为 `vite build` 报 "Cannot find module @rollup/..."。

遇到时补装即可：

```bat
cd web
npm install @esbuild/win32-x64@0.21.5 --save-exact
npm install @rollup/rollup-win32-x64-msvc@4.64.5 --save-exact
```
